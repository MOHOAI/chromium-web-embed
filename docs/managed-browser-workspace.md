# نموذج مساحة المتصفح المُدارة

## الهدف

ينشئ كل أصل ويب موثوق به مساحة مستقلة داخل Chrome بدلاً من فحص أو عرض تبويبات المستخدم الموجودة. تبدأ المساحة بتبويب جديد تجمعه الإضافة في مجموعة Chrome تحمل اسم التطبيق. لا ترى تطبيقات الويب سوى التبويبات التي أنشأتها الإضافة ضمن مساحتها الخاصة.

## نطاق الملكية

يرتبط كل سجل مساحة بـ `origin` لصفحة التطبيق وبمعرّف مساحة عشوائي. لا تُقبل أوامر القائمة أو التنقل أو الإدخال أو الالتقاط إلا لتبويب ينتمي إلى هذا السجل. تمنع هذه القاعدة موقعاً آخر من قراءة تبويبات المستخدم أو التحكم في مساحة موقع مختلف.

## الموافقة والخصوصية

يتطلب تثبيت الإضافة قبول صلاحيات `tabs` و`tabGroups` و`debugger`. بعد التثبيت، ينشئ التطبيق مساحة خاصة به عند طلب صريح من واجهته. لا يستورد النظام التبويبات المفتوحة مسبقاً إلى مساحة التطبيق ولا يعرضها. يمكن للمستخدم إنهاء المساحة أو تعطيل وضع الوكيل من واجهة التطبيق أو نافذة الإضافة.

## وضع الوكيل

وضع الوكيل هو خيار صريح لكل مساحة. عند تفعيله، يستطيع التطبيق استدعاء أوامر محددة فقط: فتح صفحة HTTP(S)، تنقل، إدخال، التقاط لقطة، وإدارة تبويبات المساحة. لا يتيح الوصول إلى ملفات الجهاز أو كلمات المرور أو تبويبات خارج المجموعة أو صفحات Chrome الداخلية. يعرض التطبيق حالة الوضع وزر إيقافه، وتتحقق الإضافة من الملكية قبل كل أمر.

## حدود Chrome

لا يمكن للإضافة تضمين واجهة Chrome الحقيقية كعنصر DOM داخل الموقع. يعرض العارض لقطات للتبويب الذي أنشأته مساحة التطبيق ويمرر أحداث الإدخال إليه من خلال Chrome DevTools Protocol. لذلك تبقى الصفحة المفتوحة داخل نافذة Chrome وتظهر بصورة تفاعلية داخل التطبيق، مع بقاء حدود أمان Chrome الأصلية قائمة.
