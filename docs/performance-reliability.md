# الأداء والاعتمادية وجودة العرض

يوازن العارض بين سرعة التفاعل ووضوح التفاصيل بنقل لقطة للتبويب النشط إلى تطبيقك، ثم تمرير أحداث الإدخال إلى Chrome محليًا. لا يوجد خادم وسيط للقطات، لكن سرعة الإطار الفعلية تعتمد على الجهاز، الصفحة المعروضة، دقة النافذة، وصلاحية `debugger` في Chrome.

> اختر الملف حسب المهمة؛ لا تعامل جودة PNG العالية باعتبارها الخيار الافتراضي لكل واجهة تشغيلية.

| ملف العرض | الافتراضي | الغرض | الاستخدام الملائم |
| --- | --- | --- | --- |
| `responsive` | JPEG، جودة 58، كل 180ms | تقليل حجم النقل وزمن الاستجابة | وكلاء المراقبة والتفاعلات السريعة |
| `balanced` | JPEG، جودة 78، كل 300ms | توازن عام | واجهة تشغيل يومية |
| `sharp` | PNG، كل 450ms | الحفاظ على حواف النص والتفاصيل | مراجعة مستندات أو واجهات دقيقة |

```ts
const viewer = new SharedTabViewer(browser, mount, {
  renderProfile: "responsive",
  pauseWhenHidden: true,
  onError(error) {
    console.error("عارض موهو:", error.message);
  },
});

await viewer.start();
// اعرض هذه القيم في أدوات تشخيص المطور، لا للمستخدم النهائي بالضرورة.
console.table(viewer.getMetrics());
```

## المقاييس المتاحة

| المقياس | المعنى | كيفية التعامل معه |
| --- | --- | --- |
| `framesRendered` | عدد اللقطات التي وصلت إلى العارض | راقب توقفه لاكتشاف عارض متجمد |
| `lastCaptureMs` | زمن آخر طلب لقطة بالمللي ثانية | قارنه بين ملفات العرض المختلفة |
| `averageCaptureLatencyMs` | متوسط زمن التقاط اللقطات خلال عمر العارض | استخدمه لتحديد صف ضغط أعلى أو صفحة ثقيلة |
| `averageRefreshIntervalMs` | متوسط الفاصل بين بدء طلبَي لقطة ناجحين | يعكس الحمل الفعلي، لا قيمة المؤقت فقط |
| `effectiveFps` | معدل الإطارات الفعلي المحسوب من الفاصل المتوسط | مؤشر تقريبي، وليس وعدًا ثابتًا لمعدل الإطارات |
| `queuedRefreshes` | عدد طلبات التحديث التي وصلت أثناء لقطة جارية | ارتفاعه يعني أن الالتقاط أبطأ من الإيقاع المطلوب |

## قواعد الاعتمادية

تُدمج طلبات اللقطات المتداخلة بدل تشغيل أكثر من التقاط في وقت واحد؛ عند وصول طلب جديد أثناء لقطة جارية، يحتفظ العارض بتحديث واحد لاحق فقط. توقف اللقطات افتراضيًا حين تكون الصفحة مخفية لتقليل الاستهلاك. أوقف العارض دائمًا عند إلغاء تركيب الصفحة عبر `dispose()`، وأغلق مساحة المتصفح إن انتهت جلسة التطبيق.

القراءات تعيد الاتصال بشكل محدود عند فقد الجسر، لأن إعادة الاستعلام آمنة. لا تعيد المكتبة تلقائيًا النقر أو الكتابة أو التنقل أو فتح تبويب؛ وهي عمليات متغيرة قد تنفذ جزئيًا قبل الانقطاع. استخدم التشخيص `reconnect-required` لعرض قرار واضح للمستخدم أو لمنطق الوكيل، ثم نفّذ `reconnect()` وأعد العملية فقط عندما يكون ذلك مقبولًا.
